# XIASS Tools 项目记忆与交接约束

> 这是一份用于长期维护与跨电脑交接的脱敏记录。它描述已确认的产品目标、非回归约束和验收标准；不保存 API Key、OAuth 回调、账户 JSON、真实本机路径、日志、用户会话或其他凭据。

> 用户的长期决策方式、协作偏好与产品验收取向见：[用户协作意识记录.md](用户协作意识记录.md)。该文件同样只保存脱敏的项目协作信息。

## 产品定位

**XIASS Tools** 是 macOS 与 Windows 的本机 Agent 配置、连接、诊断与恢复工具，不是演示页面或通用远程账户接管器。

当前受支持的本机集成包括：

- Antigravity IDE / Antigravity 2.x：保留经过验证的本地代理、补丁、模型、账户池、图片、重试、历史、启动与诊断工作流。
- Codex：管理独立的 `xiass_tools` Provider、本机模型发现、校验备份/恢复、可选历史兼容检查、OAuth / API Key / Token / JSON / 本机账号导入、额度、切换、实例和经过确认的 Desktop 生命周期协作。
- Claude Code：管理 Claude / Claude Code 的 OAuth、API Key、JSON、本机登录态导入、额度、切换和实例，以及用户明确的 Gateway、`settings.json` API 根地址、授权令牌和模型字段。
- Cursor / Windsurf：管理用户主动发起的 OAuth、Token / JSON / 本机导入、额度、切换/注入和实例；同时管理 XIASS Tools 自己拥有的 MCP 条目与校验恢复点。Cursor 另支持用户通过原生目录选择器明确选择的项目 `.cursor/mcp.json`，Windsurf 仅支持全局设置。
- 本地验证器（2FA）：标准 TOTP 导入、验证码显示、用户主动发起的加密导出，以及经密码验证和事务回滚保护的加密备份导入恢复；密钥只能存入系统凭据库。

## 最高优先级

1. **真实可用优先于界面完整。** 编译通过不代表客户可用。任何发布前都必须验证实际 App、安装包、代理启动、配置写入、恢复、退出和对应客户端链路。
2. **不破坏已验证的 Antigravity 逻辑。** 补丁、代理、图片路由、模型注入、端口处理、历史恢复和安装结构检测只能做最小必要修改；未知结构保持零写入并导出可诊断事实。
3. **Windows 与 macOS 逻辑同步。** 允许因系统 API、路径、签名、安装器和托盘机制不同而有实现差异，但 API 语义、错误边界、数据安全与用户操作结果必须对等。
4. **不伪装能力。** 未实现、未验证或不安全的功能必须显示为不可用/需要处理，不能用“已连接”“支持全部版本”“账号已授权”等文字替代真实结果。
5. **显式授权而非凭据抓取。** 默认不后台扫描、批量导入或上传浏览器 Cookie、未选择客户端的私有数据库、会话、OAuth 状态、订阅/额度存储或聊天历史。用户点击“从本机导入”“OAuth”或“切换/注入”后，可以按对应 Agent 已验证的本机规则处理必要授权资料；只有用户在设置中开启“本机账号自动导入”后，才会在本机监听五个已支持 Agent 的登录变更。原始认证文件不进入日志、诊断或未经授权的导出。

## Antigravity 不变约束

- 先发现实际安装，再按结构验证决定是否连接；绝不对未知 ASAR、JavaScript、二进制或渲染器结构强制写入。
- 已有第三方修改、旧版本助手修改或历史补丁必须先备份当前实际结构，再由可验证的事务覆盖/注入；失败时可恢复。
- 自定义模型必须真正进入 Agent 模型下拉框，并保持模型真实 ID、供应商路由和所选推理等级。
- OpenAI 兼容模型在 Antigravity 中优先稳定的 Chat Completions 兼容路径；不要擅自把普通聊天改为不受当前客户端支持的 Responses 路径。
- Claude 请求必须遵守 Anthropic 消息与工具结果协议，不能因 tool-use/tool-result 关联错误造成循环回复、重复工具调用或上下文重放。
- 网络或上游瞬时失败按设置重试同一次请求；不得重放已完成响应、无限回塞历史上下文、隐式换账户或制造会持续消耗 Token 的失败冷却。
- 图片生成路由：当前聊天模型所在供应商组内已启用的 `gpt-image-2`/Image 模型优先；本组没有时才选择其他已启用的图片供应商，并使用图片供应商自己的凭据。原生 Gemini 模型继续走原生 Gemini 生图链路。首次响应必须带可展示图片，不能要求用户二次追问。
- 文件、截图粘贴、识图、工具调用、图片显示与图片生成都必须按真实上游能力优雅降级，不能伪称支持。

## 上游、账户与模型约束

- 用户默认只填写域名与必要认证信息；应用可补全已知 API 路径，但始终保留手动完整地址编辑。
- 供应商卡片代表一个上游/账户池；模型是其内部条目。供应商可改名称、地址和认证；模型可勾选、测试、删除以及按真实模型能力调整推理等级。
- 显示名应能区分同名模型，例如 `gpt-5.6-sol · 供应商名/账户池名`；显示后缀绝不能改变实际模型 ID 或 API 路由。
- 测试应走与实际调用相同的协议/模型链路，不应以缓存结果替代上游可用性。
- OAuth、API Key、JSON 导入、Refresh Token 等不同登录模式只显示相应字段。自动回调失败时可支持用户主动粘贴回调 URL 或 `code`；不得向渲染层、日志或诊断包输出密钥、state、回调内容或令牌。
- 账户等级、额度或用量只能显示由相应已授权上游明确返回、且产品实际支持读取的安全数据；不能伪造官方账号、订阅或额度。

## XIASS Tools 本机配置边界

| 集成 | 可以做 | 不可以声称或实现为自动能力 |
| --- | --- | --- |
| Codex | `config.toml` Provider、上游模型发现、校验备份/恢复、显式历史兼容；用户主动 OAuth、API Key / Token / JSON、本机 Codex / ChatGPT Desktop 导入、额度刷新、账号切换和实例 | 不后台读取 `auth.json` 或官方会话；不把认证文件纳入统一备份/诊断；不伪造订阅/额度；不对未确认目标强制结束进程 |
| Claude Code | Claude / Claude Code 的 OAuth、API Key、JSON、本机登录态导入、额度、切换和实例；用户明确的 `settings.json` / Gateway 配置与备份恢复 | 不自动扫描未选择的 Claude 数据；不处理项目设置或 MCP 以外的未授权数据；不把凭据写入日志、诊断或共享状态 |
| Cursor / Windsurf | OAuth、Token / JSON / 本机导入、额度刷新、账号注入、多实例，以及 XIASS MCP 条目和恢复点 | 不后台读取认证存储；仅在用户导入或切换时处理必要的客户端认证数据；不接管未选择账户、其他 MCP、聊天或无关数据库 |
| TOTP | 本机系统凭据库、标准 TOTP、加密导出与加密备份导入恢复 | 将密钥写入 `localStorage`、日志、诊断、共享状态或明文文件 |

## 品牌与兼容性规则

- 对外可见产品名称、App、安装包、界面、诊断标题和新建数据优先使用 **XIASS Tools**。
- 历史 `BYOK` / `Antigravity WF` 标记、旧数据目录、旧补丁路由、安装器 receipt、环境变量和备份标识可能是老版本升级、恢复或现有 Antigravity 注入兼容所必需的输入。**不能全局替换或删除。**
- 迁移策略是“新写入采用新品牌，旧标识仅作为受限兼容输入继续识别”。修改任一旧标识前，必须有跨版本补丁/恢复回归证据。
- 不在用户界面、普通诊断摘要、默认日志或新建备份名称中暴露历史品牌；若为了兼容保留，只能放在内部受控解析逻辑中。

## 生命周期、界面与隐私

- 关闭窗口按系统约定进入后台；显式“退出”才停止本地代理并释放端口。macOS 菜单栏与 Windows 通知区域都需要可打开主界面和退出。
- 不展示内部监听端口；用户只看“本地代理已启动/未启动”等可操作状态。
- UI 支持浅色、深色、跟随系统；每次改动都检查文字、边框、状态色、焦点和模态层级。
- 模态编辑器必须防止误点背景关闭；密钥草稿、TOTP 密钥、导出密码、OAuth 回调只能保持在局部短生命周期状态。
- 首次使用引导应清楚：连接 Antigravity → 添加上游/获取模型/测试并添加 → 回首页启动目标应用。
- 面向客户的诊断导出应包含足够的版本、安装识别、补丁、代理、模型注入、图片与异常状态，但必须二次脱敏并排除密钥、Token、Cookie、账户 JSON、会话和图片数据。

## 发布与验收

发布不能只依靠某一台开发机。每个版本至少要求：

1. macOS 与 Windows 的版本号、UI 文案、Wails 元数据、更新器常量、安装器文件名和 README 版本一致。
2. 前端全量测试、Go 单元测试/race、`go vet`、`git diff --check` 通过。
3. macOS Universal App 同时包含 `arm64` 与 `x86_64`，签名校验通过；PKG 只含 `XIASS Tools.app` 的一个正式可执行文件与必要资源。
4. Windows 需要原生 x64 Wails 构建、NSIS Setup 构建与实际安装验证。macOS 交叉编译不能代替 Windows GUI/托盘/安装器验证。
5. Wails 生成绑定必须在每个平台原生构建后核验，确保 Codex、Claude Code、Cursor、Windsurf、MCP 恢复点和 TOTP 方法都实际存在。
6. 安装后实际验证：启动、配置、备份/恢复、退出释放端口、Antigravity 连接、模型下拉框、文本、工具、文件/图片输入、图片生成、重试和诊断导出。
7. Release 只发布标准 macOS Universal PKG、Windows x64 Setup EXE 与 `SHA256SUMS.txt`；不要混入 portable、独立 EXE、ZIP 或历史测试产物。
8. 未使用 Apple Developer ID/公证或 Windows 商业签名时，必须如实说明 Gatekeeper/SmartScreen 影响；不能写成“无提示安装”。

## 维护行为

- 每次改稳定链路前先阅读对应 macOS 和 Windows 实现、既有测试与近期诊断证据。
- 不执行 `git reset --hard`、`git checkout --`、`git clean` 或宽泛删除命令清理脏工作区。
- 不把 API Key、GitHub PAT、OAuth Token、真实路径、PID、回调地址或账户文件复制进源码、提交、日志、诊断或聊天记录。
- 已经出现在历史聊天中的访问令牌应视为泄露；应由持有人在服务端撤销并重建最小权限凭据，而不是再次发送到对话中。
